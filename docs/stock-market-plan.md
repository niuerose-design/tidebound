# 서브게임 '주화 증권거래소' (기획안)

> 작성 2026-10-09. 아직 코드를 바꾸지 않았습니다. 9장 '결정할 것'을 정한 뒤 구현합니다.

## 1. 한 줄 요약

가상의 종목 6개에 **던전 주화**로 투자하고, 10분마다 바뀌는 시세에 따라 손해 또는 이익을 보는 서브게임.
**새 DB 표 · 예약 작업(cron) · 실시간 연결 없이** 만들 수 있습니다. 시세는 저장하지 않고 '시각 → 가격' 계산식으로 그때그때 구하고,
보유 주식은 지금 세이브(State)에 몇 줄 더할 뿐이라 매수 · 매도 한 번은 주화 상점 구매 한 번과 같은 비용입니다.

## 2. 지금 구조 (사실 확인)

- 행동은 모두 `POST /api/game` → `mutate()`(`game/server/store.ts`)에서 세이브 한 번 읽고 한 번 씁니다. 주화 상점도 같습니다(`game/systems/actions/dungeon-shop.ts`).
- 화면은 원래 5초(전투 화면) · 15초(다른 화면) · 60초(대기) 간격으로 `sync`를 보냅니다(`components/game/use-game.ts`). 시세가 10분 단위로만 바뀌면 **추가 폴링이 필요 없습니다**.
- 던전 주화: `State.dungeonCoins`. 환생해도 남고 승천하면 사라집니다. 헬 하루 보너스 수입 ≈ 1,200주화(`game/data/dungeon-shop.ts`).
- 서버 전용 비밀 값은 `game/secret/`과 `game/server/secrecy.ts`(해시 · 카탈로그 키) 방식이 이미 있습니다.
- 참고: v3.208에서 판돈을 거는 '랜덤게임'을 삭제했습니다. 같은 이유(9장 1번)에 걸리지 않는지 먼저 확인이 필요합니다.

## 3. 서버 부하 0을 만드는 핵심 설계

### 3-1. 시세는 저장하지 않는다 (결정론적 계산)

- 시간을 10분 칸(틱)으로 나눕니다: `tick = floor(now / 10분)`.
- 각 틱의 충격값 `ε(종목, tick) = hash(MARKET_SECRET, 종목 id, tick)` → 정규분포 근사값(-3~+3).
- 로그 가격은 평균으로 돌아가는 AR(1) 과정:
  `logP(t) = λ · logP(t-1) + σ · ε(t)` (λ = 0.98, 기준가로 끌려옴)
- 어떤 시각의 가격이든 **그 시각 300틱 전부터 0으로 시작해 돌리면** 같은 값이 나옵니다(λ³⁰⁰ ≈ 0.002라 시작점 영향이 사라짐).
  → 어느 서버 인스턴스에서 계산해도 같은 가격, 기록 저장이 필요 없음. 종목 6개 × 444틱 ≈ 2,700번 해시 = 1ms 미만.
- 가격 = `기준가 × exp(logP)`, 기준가의 0.2배~5배로 자릅니다.

### 3-2. 미래 시세 유출 막기

- 계산식이 화면 코드에 들어가면 미래 가격을 미리 알 수 있습니다. 그래서 `MARKET_SECRET`은 **서버 전용 환경 변수**(또는 `game/secret/`)에만 두고,
  화면에는 **지금 틱까지의 가격만** 보냅니다.

### 3-3. 시세판 전송: CDN 캐시

- 시세는 모든 유저에게 같으므로 `GET /api/market`(로그인 불필요)을 만들고 `Cache-Control: public, s-maxage=<다음 틱까지 남은 초>`로 응답합니다.
  → 10분에 **함수 실행 약 1번**(Vercel 엣지 캐시), DB 접근 0. 응답 크기 ≈ 종목 6개 × 최근 144틱(하루) ≈ 5KB.
- 거래소 화면을 열었을 때만, 그리고 틱이 바뀌었을 때만 받습니다. `sync` 응답에는 아무것도 더하지 않습니다.

### 3-4. 보유 주식은 세이브에

```ts
// game/types.ts State에 추가
market?: {
    holdings: Record<string, { qty: number; cost: number }>; // 종목 → 수량 · 매수 원금 합(주화)
    day?: string; trades?: number;                            // 오늘(한국 시간) 거래 수
    realized?: number;                                        // 누적 실현 손익(통계 · 칭호용)
};
```

- 매수 · 매도 = 행동 `{ type: 'market', id: '<종목>', value: '+N' | '-N' }`. 서버가 **행동을 처리하는 순간의 틱 가격**으로 체결합니다(화면이 보낸 가격은 믿지 않음).
- 부재중에도 시세는 계산식대로 흘러가므로 따로 정산할 것이 없습니다. 팔 때 한 번 계산하면 끝.

### 3-5. 부하 비교

| 항목 | 추가 비용 |
|---|---|
| DB 표 | 없음 |
| 예약 작업 · 웹소켓 | 없음 |
| 시세판 | 10분당 함수 1회(캐시), DB 0 |
| 매수 · 매도 | 주화 상점 구매와 같음(세이브 읽기 1 · 쓰기 1), 하루 거래 수 제한 |
| 세이브 크기 | 종목 6개 × 2숫자 ≈ 200바이트 |

## 4. 종목 (세계관 연동, 안)

| 종목 | 성격 | 하루 변동(σ 기준) | 기준가 |
|---|---|---|---|
| 리스항구 해운 | 안정 | 약 3% | 100 |
| 헤네시스 버섯농장 | 안정 | 약 4% | 50 |
| 페리온 광산 | 보통 | 약 8% | 200 |
| 엘리니아 마법학회 | 보통 | 약 10% | 150 |
| 커닝시티 상회 | 고위험 | 약 20%, 가끔 급등락 | 30 |
| 아케인 리버 탐사 | 고위험 | 약 25%, 가끔 급등락 | 500 |

- 하루 변동 ≈ 틱당 σ × √144 = 12σ. 고위험 종목은 틱마다 작은 확률(예: 0.5%)로 ±15~30% 급등락 충격을 더합니다.

## 5. 재미 요소: 시황 소문

- 틱마다 해시로 '소문'을 만듭니다(예: "페리온 광산에서 새 광맥 소문"). 소문은 **다음 틱 충격의 부호를 70% 확률로 맞힙니다**.
- 소문도 서버가 지금 틱까지만 보내므로, 미리 알 수 있는 건 '다음 10분의 경향 70%'뿐. 수수료(6장)보다 기대 이익이 작게 맞춰 '정답 공략'이 생기지 않게 합니다.
- 선택: 서버 이벤트(`events-config.ts`)나 해킹(`hacks.ts`)과 연결 — 예: 해커의 '시세 조작' 효과. 1차 범위에서는 뺍니다.

## 6. 경제 균형 (주화 인플레이션 방지)

던전 주화는 칠흑 · 코어 · 장비 상자로 바뀌는 성장 재화라, 거래소가 **주화를 찍어내는 곳이 되면 안 됩니다**.

- 기대 수익 0: 평균 회귀 과정이라 오래 들고 있어도 평균은 기준가. 수수료가 있으니 기대값은 약간 마이너스(=주화 소각처).
- 수수료: 매수 · 매도 각 1%(최소 1주화). 소문 적중률 70% × 평균 변동으로 얻는 기대 이익이 왕복 수수료 2%보다 작게 맞춥니다(구현 때 시뮬레이션 스크립트로 확인).
- 투자 한도: 총 보유 원금 최대 **3,000주화**(헬 하루 보너스 약 2.5일분). 큰 이익 · 큰 손실 모두 며칠 수입 안으로 묶습니다.
- 하루 거래 20회(한국 시간 자정 초기화). 세이브 쓰기 횟수도 함께 묶입니다.
- 가격 하한 0.2배: 고위험 종목도 원금 전부를 잃지는 않습니다('상장폐지'는 9장에서 결정).

## 7. 승천 · 환생 · 슬롯

- 환생: 보유 주식 유지(주화와 같음).
- 승천: 주화처럼 **보유 주식도 사라집니다**(승천 직전 매도 안내 문구를 승천 확인창에 추가).
- 캐릭터 슬롯마다 따로(주화가 슬롯별이라 같음).

## 8. 화면

- 위치: 던전 탭 → '주화 상점' 옆에 '증권거래소' 카드(또는 던전 주화 상점 패널 안 탭).
- 종목 목록: 현재가 · 오늘 등락률 · 미니 차트(최근 144틱, 기존 `dataviz` 규칙의 스파크라인).
- 종목 상세: 하루 차트, 지금 소문, 보유 수량 · 평균 단가 · 평가 손익, 매수 · 매도 수량 입력과 수수료 미리보기.
- 다음 시세 갱신까지 남은 시간(화면 타이머, 서버 호출 없음).
- 기록: 오늘 거래 수, 누적 실현 손익. 선택: 누적 손익 업적 · 칭호('개미', '큰손').

## 9. 결정할 것

1. **v3.208에서 랜덤게임을 지운 이유와 겹치지 않는지.** 판돈형 콘텐츠를 피하려는 것이었다면, 이 거래소도 같은 판단을 받을 수 있습니다.
2. 투자 한도(3,000주화) · 하루 거래 수(20) · 수수료(1%) 수치.
3. 시세 갱신 간격: 10분(권장) / 30분 / 1시간. 짧을수록 자주 들르는 재미, 길수록 덜 피곤함.
4. 소문 기능을 1차에 넣을지.
5. 고위험 종목 '상장폐지'(드물게 가치 0) 이벤트 여부.
6. 랭킹(주간 수익률)을 넣을지. 넣으면 기존 랭킹 저장소에 주 1회 · 변화 있을 때만 올리는 방식으로 부하를 묶습니다.
