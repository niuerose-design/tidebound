# 화면 글쓰기 규칙

플레이어가 읽는 모든 문장(화면 · 도움말 · 업적 · 연구 · 장비 옵션 · 전투 로그)에 적용합니다. 목표는 "기계가 설명을 늘어놓은 글"이 아니라 "게임이 말을 거는 글"입니다. 숫자 기준은 `scripts/check-writing.mjs`가 재고, CI가 돌립니다.

## 꼭 지키는 규칙

| 규칙 | 기준 | 점검 |
|---|---|---|
| 버전 번호 금지 | 플레이어 문장에 `v3.201` 같은 번호를 쓰지 않습니다. 바뀐 이력은 업데이트 내역에만 둡니다. | 금지(하나라도 있으면 실패) |
| 괄호 보충 금지 | 괄호 안에 조건 · 예외 · 이유를 넣지 않습니다. 괄호는 단위 · 수식(`(최대 5)`, `(레벨 + 2) × 배율`)에만 씁니다. 설명이 필요하면 문장을 끊거나 도움말로 보냅니다. | 래칫 |
| 나열은 셋까지 | 가운뎃점(` · `) 나열은 같은 종류 셋까지. 넷 이상이면 표 · 줄바꿈 · 칩으로 바꿉니다. | 래칫(4개 이상) |
| 한 문장 한 뜻 | 한 문자열은 120자를 넘지 않습니다. 화면의 안내문(`Note`)은 한 문장. 나머지는 도움말 한 곳에만 둡니다. | 래칫(120자 초과) |
| 설명은 한 곳에 | 같은 규칙을 레이블 옆 · 카드 아래 · 도움말에 세 번 적지 않습니다. 화면에는 값과 동사, 규칙은 도움말. | 검토 |
| 버튼은 동사 | "장착", "바치기", "환생". 명사형("환생하기 버튼")이나 설명형("여기를 눌러 환생")을 쓰지 않습니다. | 검토 |
| 빈 상태는 다음 행동 | "아직 기록이 없습니다"로 끝내지 않고 무엇을 하면 채워지는지 한 줄 더 둡니다. | 검토 |
| 개발 사정 금지 | "운영 결정으로", "전에는 …였음", "버그 수정" 같은 말은 화면에 쓰지 않습니다. | 검토 |

## 고치기 전 · 후

| 전 | 후 |
|---|---|
| 골드 획득 +10%(v3.201부터 던전은 골드 대신 주화를 줌) | 골드 획득 +10%. 던전은 골드 대신 주화를 주므로 사냥터에서만 듭니다. |
| 환생 횟수 24 | 환생 횟수 보상 24. 20회까지 회당 1, 그 뒤 √(횟수 − 20) |
| 아제로스 직업 5개를 해금합니다(전직 화면의 '전직해 본' 수 · 숙달과는 다름). | 아제로스 직업 5개에 전직해 봅니다. |
| 무릉도장 전용(v3.188 새로 붙지 않음). 물리 공격이 크게 오릅니다. | 옛 무릉도장 옵션. 물리 공격이 크게 오르고, 새로 붙지 않습니다. |
| 현재 · 숙달 · 해금함 · 전직 가능 · 조건 부족 · 미발견 | (상태 칩 여섯 개를 색 · 아이콘과 함께 따로 둠) |

## 래칫이란

`scripts/data/writing-baseline.json`에 파일마다 지금 남아 있는 위반 수를 적어 둡니다. 점검은 파일의 수가 기준보다 **늘면** 실패하고, 줄면 통과합니다. 줄였으면 기준을 다시 씁니다.

```bash
node scripts/check-writing.mjs            # 점검
node scripts/check-writing.mjs --list     # 위반 목록(규칙 이름을 붙이면 그 규칙만: --list paren)
node scripts/check-writing.mjs --update   # 줄인 뒤 기준 갱신(늘리는 데 쓰지 않음)
```

새 화면 · 새 문장은 기준이 0이므로 규칙을 그대로 지켜야 합니다. 옛 문장은 아래 순서로 정리합니다.

## 정리 순서 (PR 단위)

1. **규칙과 점검** — 이 문서, 점검 스크립트, 버전 번호 전부 제거. (완료)
2. **자료 문자열** — 업적 · 연구 · 장비 옵션 · 상태이상 · 공개 스킬 설명의 괄호 보충을 문장으로. 직업 · 계보 · 확장 스킬 · 원정대 설명까지. (완료, v3.448 · v3.449. 자료 문자열에 남은 괄호는 수식뿐)
3. **안내문 다이어트** — 120자 넘는 `Note` 21개를 한 문장 + `FinePrint`(접힌 자세한 규칙, `<p>` 하나에 한 뜻)로 나눴습니다. (완료, v3.450) 새 안내문도 같은 모양으로: 화면에는 지금 필요한 한 문장, 규칙은 FinePrint.
4. **화면별 리듬** — 사냥 · 던전은 상태 중심(큰 숫자 · 적은 글), 보관함 · 상점은 목록, 기록 · 업적은 표. 한두 화면씩.
   - 목표 · 업적(v3.451): 업적 344장 카드 격자 → 같은 묶음의 단계를 한 줄로 합친 줄 120여 개(단계 점 · 진행 · 보상 · 받기). 휴대폰 화면 길이 36,900px → 9,900px.
   - 전직(v3.452): 계보 카드 3줄 → 2줄 표(그림 · 이름 · 전직해 본 n / m, 차수 점 · 상태 수). 현재 직업 판은 문장 대신 숙련 · 전직해 본 · 숙달 세 칸. 태그 칩은 휴대폰에서 가로 스크롤 한 줄.
   - 통계 · 기록(v3.453): 전투 기록을 몹마다 접힌 카드 묶음에서 표(결과 · 턴 · 준 피해 · 최고 · 받은 피해 · 때, 줄을 펼치면 로그)로. 지난 승리 대비 변화는 턴 · 최고 칸에 작은 수치로. 실시간 효율의 설명 문단과 전투 기록 보관 규칙은 FinePrint. 업데이트 화면의 개발 사정 문구 삭제.
   - 보관함 · 상점(v3.454): 재화 타일을 휴대폰에서 2열로 줄여 목록이 바로 보이게. 화면 머리 설명 한 문장. 상점 안쪽 탭이 둘째 줄로 넘어갈 때 내용과 겹치던 것을 고침. 강화 · 유물 · 던전 주화 상점의 괄호 보충 40여 곳을 문장으로.
   - 사냥(v3.454): 휴대폰에서 모험가 카드 바로 아래에 장면이 오고, 난이도와 실시간 효율은 그 아래(상태 중심). 4단계 끝.
5. **도움말 재구성** — effect · condition · limit 세 칸 틀을 버리고 질문형 항목으로. (완료, v3.455) 41개 규칙 카드가 “환생하면 무엇을 받고 무엇이 남나요?” 같은 질문 줄이 되고, 누르면 답 문단이 펼쳐집니다. 주제 요약은 제목 아래 줄로.
